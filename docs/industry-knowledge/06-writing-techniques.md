# 06. 記事ライティング技術（コピーライティング・Web文章術）

> 作成日: 2026-09-26。目的は「読者満足度を上げる書き方」の共通ルール化。記事執筆前に必ず確認する。
> **根拠の強さを明記**: 【一次】=調査・公式ドキュメント／【定説】=広く使われる型（実証データは未確認）／【業者ブログ】=二次情報。
> 「型」は思考の補助であり、**量産テンプレ化は禁止**（[[feedback_no_template_duplication_across_area_articles]]、Googleのscaled content abuse規制と直結）。

---

## 1. 読者は「読まない」前提で書く【一次】

出典: NN/g "How Users Read on the Web"（https://www.nngroup.com/articles/how-users-read-on-the-web/）

- テストユーザーの**79%は常にスキャン、単語単位で読むのは16%**。
- ネブラスカ観光情報の5バージョン比較（ユーザビリティ改善率）:
  - 簡潔（語数半分）: **+58%**
  - スキャンしやすい構成（箇条書き等）: **+47%**
  - 客観的な言葉遣い（誇張なし）: **+27%**
  - 3つ全部: **+124%**
- 「宣伝的な言葉は読者に認知的負担をかける」。形容詞（素晴らしい・圧倒的）・バズワード・根拠のない主張を削ると信頼される。
- B2B・高学歴読者でも同じ。「簡潔・スキャンしやすい・事実で検証可能」を求める（https://www.nngroup.com/articles/writing-for-lower-literacy-users/ 周辺の記述）。管理組合理事・ビル管理者もこの層。

**適用ルール**
1. 1段落1論点。見出しだけ拾い読みしても記事の主張が通る構成にする。
2. 見出しは中身の要約（「〜について」「まとめ」のような空見出し禁止）。
3. 「業界最安」「圧倒的」「安心」等の主観形容詞は原則使わない。数字・条文・出典で語る。
4. 結論を先に置く（逆ピラミッド）。重要語は太字（黄色ハイライトspanは禁止: [[feedback_no_yellow_highlight_span]]）。
5. 「語数半分」は原則であり、6,000〜10,000字ルールとは緊張関係がある。**字数を稼ぐための水増しは削り、網羅性は情報の種類を増やして満たす**（水増し＝簡潔性を損ない満足度が下がる）。

## 2. Google公式が問う「良い記事」の自己診断【一次】

出典: https://developers.google.com/search/docs/fundamentals/creating-helpful-content

執筆後のチェックに使う（抜粋・要約）:
- 独自の情報・調査・分析があるか／明白な内容を超える洞察があるか
- 見出し・タイトルが**内容を正確に要約**し、誇張や煽りがないか
- ブックマークして人に勧めたくなるか／検索上位の他ページと比べて実質的な価値があるか
- 誤字・文体の乱れ・雑な作りがないか
- **専門家/熟知した人が書いた・確認したと分かるか、事実誤認がすぐ検証できる形で無いか**
- 危険信号: 他者の要約に終始／流行ネタ追い／自動化で多トピック量産／**読了後に「他で調べ直さないと」と感じさせる**

→ 最後の項目が満足度の本質。「この記事だけで意思決定に必要な情報が揃う」をゴールに置く。

## 3. 構成の「型」の使い分け【定説・業者ブログベース】

出典: 各種解説（https://www.asobou.co.jp/blog/web/writing-format ほか）。効果の実証比較データは確認できていない。

| 型 | 構造 | 向く場面（oyazunaでの使いどころ） |
|---|---|---|
| **PREP** | 結論→理由→具体例→結論 | 説明・解説記事の各セクション。最も汎用。法規制の解説、工法比較 |
| **PASONA**(神田昌典) | 問題→親近感→解決策→絞込→行動 | 課題起点のLP・リード導線。「足場が組めない」「見積が高い」型の悩み記事の冒頭 |
| **新PASONA** | 問題→扇動→商品→絞込→限定→行動 | 販売LP向け。**煽り要素が強く、BtoB・不安訴求は誠実さを損なうリスク。oyazunaでは原則使わない** |
| **QUEST** | 対象宣言→共感→教育→刺激→移行 | 対象読者が明確な記事（「マンション管理組合の理事の方へ」）。冒頭で読者を絞るのに有効 |
| **AIDA/AIDMA** | 注意→興味→欲求(→記憶)→行動 | 広告・バナー・タイトル設計の発想法 |
| **BEAF** | 特徴→根拠→利点→行動 | 掲載企業・工法の紹介文 |

**運用方針**
- 記事全体を1つの型に当てはめない。**導入=QUEST/PASONA的（誰の何の悩みか）、各節=PREP、企業紹介=BEAF**が現実的。
- 型は骨格の確認用。文言・見出しまで同じ型にすると横展開記事の重複問題になる。
- 「限定」「今だけ」等の緊急性煽りは使わない（誠実さ・[[feedback_no_speculation_in_content]]）。

## 4. タイトル・導入文【業者ブログ／定説】

- タイトルの字数を機械的に管理するのはしない（2026-09-28、ユーザー指示で撤回。今まで通りの付け方でよい）。
- **具体的な数字**（費用・年数・件数・条文）と**ベネフィット**を入れる。ただし誇張・煽りはGoogle自己診断で減点（上記§2）。
- Ogilvyの有名な主張「見出しを読む人は本文の5倍」「見出しを書いた時点で予算の80%を使った」は原典著書に基づく広告業界の**経験則**（実験データではない）。要旨は「**巧妙さより明確さ。読者は速く読むので意味が一瞬で分かること**」。
- 導入文は200〜300字が目安（業者ブログ）。構成要素: **共感→結論（この記事で分かること）→根拠→ベネフィット→行動**。導入文は本文完成後に要約として書くと崩れにくい。

## 5. 日本語Webライティングの基本【業者ブログ、複数一致】

- **一文一義**を意識する（1つの文に論点を詰め込みすぎない）。ただし具体的な字数目安(40〜60字等)による機械的な管理はしない（2026-09-28、ユーザー指示で撤回。今まで通りの自然な長さで書く）。
- 結論ファースト、専門用語は初出で言い換え、箇条書き・表・図で視覚化。
- 読者が少しでも分かりにくいと感じたら即離脱するという指摘が一致。
- **知識の呪い**（詳しい人ほど読者の前提知識を過大評価する）に注意。NN/gは「読者が日常的に使う語ならジャーゴンではない」とする。oyazunaでは、発注者（管理組合・オーナー）は「ロープアクセス」「12条点検」を**知らない前提**で、初出で1行の説明を入れる。
- 古賀史健『20歳の自分に受けさせたい文章講義』の要点（検索結果で確認できた範囲）: 「書こうとせず、頭の中のもやもやを**読者に向けて翻訳**する」「推敲は不要な箇所を惜しまず削る」。詳細な章立ては未確認のため引用は控える。

## 6. 信頼を生む書き方（oyazuna向けの実務原則）

1. **数字は出典付き**。出典が業者ブログ止まりなら「〜とされる」「業者により差がある」と書き、断定しない。
2. **一次体験を入れる**（Googleの一次体験評価、[[05-google-seo-policy-2026]]）。掲載企業へのヒアリング・実際の見積・施工事例など、他社が書けない材料を優先。
3. **読者の次の行動まで書く**。BtoBは相見積もり・稟議・理事会資料・保険/資格確認まで（[[feedback_area_articles_bto_b_depth_requirement]]）。
4. **デメリット・向かないケースも書く**（例: ロープアクセスは養生不可・天候に弱い）。誇張のない記述は信頼につながる（NN/gの客観性の知見と整合）。
5. 「〜と言われています」の連発を避ける。言い切れない場合は「未確認」「業者によって異なる」と書き、読者に確認を促す。

## 7. 執筆後チェックリスト

- [ ] タイトルは内容の正確な要約か（誇張なし、数字/具体語あり。字数の目安チェックはしない）
- [ ] 導入文で「誰の、どんな悩みに、何が分かるか」が200〜300字で示されているか
- [ ] 見出しだけ拾い読みして主張が分かるか
- [ ] 各節は結論から始まっているか（PREP）
- [ ] 一文一義になっているか（字数の機械的なチェックはしない）／初出の専門用語に説明があるか
- [ ] 主観形容詞・煽り・限定表現を使っていないか
- [ ] 数字・制度に出典があるか／推測を断定していないか
- [ ] 水増しの段落はないか（削って読者の時間を節約）
- [ ] 読了後に「他で調べ直さないと」と感じさせない網羅性があるか（発注の流れ・比較・注意点）
- [ ] 他の横展開記事と見出し・言い回しが酷似していないか
- [ ] スマホで表・段落が崩れていないか
